# Fixed choices for the T1 robustness tests

The following choices were fixed before any model output on the stress sets was seen. Recorded 2026-11-13.

- **No manual adjustments:** the typo probability was fixed at 0.15 with no readability adjustment (15 before/after pairs are saved in `build_log.json` for review); out-of-scope items were removed only by the fixed keyword filter, with no manual screening; the first Claude batch of each set had to pass an automatic gate (below) before the set continued; usage or rate limits were waited out in 30-minute steps for up to 12 hours per set. No Claude run on the full 3,076-message test set was made.
- **CLINC dataset:** `clinc/clinc_oos` has configs `imbalanced`, `plus` and `small`; the out-of-scope intent is `oos` (id 42) in all of them. The `plus` config was used because it has the most oos training items (250 vs 100). The test split has 1,000 oos items in every config.
- **Not enough oos training items for S3 + S2 from one split.** After the keyword filter, 235 of the 250 `plus` train oos items remain; S3 takes 200 (Random(654) order). The 100 S2 validation oos items are drawn with Random(655) from the 35 leftover train items plus the 95 filtered `plus` validation-split oos items. The CLINC test split is used only for the out-of-scope test items. No item appears in two groups (checked by assertion).
- **S2 validation in-scope items:** 500 Banking77 train examples outside that seed's 2,000-example subset, drawn with Random(555 + seed).
- **S2 confidence score:** probability of the greedy answer = product of its token probabilities up to and including the end-of-turn token. Threshold rule: answer `none_of_these` when confidence < threshold; threshold chosen to maximise overall accuracy on the validation set, candidates 0, every validation confidence value and just above 1; ties go to the lowest threshold. Chosen once per seed, saved to `s2_thresholds.json`, never re-chosen.
- **Extended prompt (C1, S1, S3):** `system_prompt(labels + ["none_of_these"])` (so `none_of_these` is one extra line at the end of the label list) followed by a blank line and "If a message does not fit any label, answer none_of_these." Claude gets the same text plus the unchanged batch JSON paragraph.
- **Test A row order:** stored in the T1 Claude batch order (Random(456)), so Claude's typo batches hold the same messages as its clean T1 batches.
- **Test B re-pairing:** equal-label pairs are broken up and re-paired greedily in shuffled order with the first remaining item of a different label; unpairable items are dropped and counted.
- **Partial Claude batches:** if a set's size is not a multiple of 25, the last batch's JSON instruction says that batch's size instead of 25 (only the number changes).
- **Claude gate:** the first batch of each set must have exit code 0, `num_turns == 1`, a JSON array of the right length, model `claude-opus-5-5` and at least n−2 allowed labels (23 of 25). Transient errors (timeouts, non-zero exit without a usage message, unparseable CLI output) first get retries after 30 s, 2 min and 10 min; any other gate failure gets one retry after 60 s.
- **Clean reference numbers** for drops are the T1 results on the same 500 messages (`results/preds_Qwen3-4B-Instruct-2507_n2000_s*.jsonl` and `results/preds_claude_code_sample500.jsonl`), read only.
- **Environment of the Claude calls (difference from T1):** the T1 baseline calls were launched from a shell with Claude Code session environment variables set (about 17 `CLAUDE_*` variables, for example `CLAUDECODE=1` and `CLAUDE_CODE_CHILD_SESSION=1`); the stress-test calls were launched from a clean environment, with every `CLAUDE*`/`AI_AGENT` variable except `CLAUDE_BIN` cleared. The model, flags, prompt format and isolation are otherwise the same. It is not known whether those variables changed the CLI's behaviour in T1; the clean-vs-stressed Claude drops carry this small extra difference.
- **CLI binary:** the Claude Code CLI binary bundled with its editor extension was used (version 2.1.322), resolved at the start of every Claude stage.
- **Test run call kept:** one Claude call made during a test run of the pipeline (Test A batch 0, from a clean environment, gate passed 25/25) used a `typo500.jsonl` byte-identical to the frozen file and the same prompt, so its predictions were kept as batch 0. It is included in the reported call count; the pipeline resumed Test A at batch 1.
- **Test run finding fixed before the real run:** the report computes the small model's clean accuracy on exactly the messages it has stressed predictions for (paired drops).
