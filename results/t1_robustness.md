## What this means for production

- **Typos (Test A):** the small model dropped 0.8 points from its clean score, Claude dropped 0.6. The small model degraded more, by 0.2 points.
- **Two issues in one message (Test B, either-match):** the small model dropped 3.4 points from its clean score, Claude dropped 1.2. The small model degraded more, by 2.1 points.
- **Out-of-scope messages (Test C):** Claude (C1) kept 0.882 in-scope accuracy with 0.995 out-of-scope recall; S1 0.907 in-scope / 0.835 recall; S2 0.893 in-scope / 0.810 recall; S3 0.913 in-scope / 0.990 recall.

Differences inside the seed spread or with McNemar p ≥ 0.05 should be read as ties.

## Test construction (frozen before any model output)

- **Base set:** the 500 test indices in `results/sample500.json` (`random.Random(123)`).
- **Test A:** per message `random.Random(1000 + idx)`; lowercase; remove all punctuation except apostrophes; each word of 4+ letters (no digits) gets, with probability 0.15, one edit chosen uniformly from: swap two adjacent inner letters, delete an inner letter, duplicate an inner letter, replace an inner letter with a QWERTY neighbour. Probability fixed at 0.15 (unattended rule).
- **Test B:** base indices shuffled with `random.Random(789)`, paired off, equal-label pairs re-paired; text `"<A> Also, <b lowercased first letter>"`.
- **Test C:** CLINC150 `oos` items only (never in-scope CLINC intents), fixed banking-keyword filter, 500 base + out-of-scope test items shuffled with `random.Random(987)`.
- **Prompts:** original `system_prompt(labels)` from `exp1_routing.py` for A, B and S2; the extended prompt (one extra label line `none_of_these` plus "If a message does not fit any label, answer none_of_these.") for C1, S1 and S3. Claude gets the same text plus the batch JSON paragraph.

Counts: typo500 500, typo_messages_with_at_least_one_edit 257, merged_pairs 249, merged_equal_label_pairs_redrawn 1, merged_dropped 2, oos_test 200, oos_s3_train 200, oos_s2_val 100, oos_removed_by_filter 44, oos_mixed 700.

### Decisions recorded by the build stage

- Test A rows are stored in the T1 Claude batch order (results/sample500_batch_order.json, Random(456)), so Claude's typo batches contain the same messages as its clean T1 batches.
- Test B re-pairing: items from equal-label pairs (and any odd item) are re-paired greedily in shuffled order with the first remaining item of a different label; unpairable items are dropped.
- CLINC source: clinc/clinc_oos, config 'plus' (the config with the most oos train examples: 250; 'small' and 'imbalanced' have 100). oos intent id 42.
- S2 validation oos items: 100 drawn with Random(655) from the 'plus' train oos items not used by S3 plus the 'plus' validation-split oos items, because the train split alone cannot supply 200 (S3) + 100 (S2) after filtering. The test split is never used for either.
- S2 validation in-scope items: 500 Banking77 train examples not in that seed's 2,000-example subset, drawn with Random(555 + seed).

## Decisions and deviations (recorded during setup)

Made during an unattended run, by the rules of the (unpublished) run plan for the robustness tests. Recorded 2026-11-13.

- **Unattended overrides applied:** typo probability fixed at 0.15 (no readability adjustment; 15 pairs saved for later review); out-of-scope items removed only by the fixed keyword filter (no manual skim); one automatic gate batch per Claude set instead of showing the owner; rate limits waited out (30 min steps, 12 h per set); optional full-test-set Claude run not done.
- **CLINC dataset:** `clinc/clinc_oos` exists with configs `imbalanced`, `plus`, `small`; the out-of-scope intent is `oos` (id 42) in all of them. Used `plus` because it has the most oos training items (250 vs 100). The test split has 1,000 oos items in every config.
- **Not enough oos training items for S3 + S2 from one split.** After the keyword filter, 235 of the 250 `plus` train oos items remain; S3 takes 200 (Random(654) order). The 100 S2 validation oos items are drawn with Random(655) from the 35 leftover train items plus the 95 filtered `plus` validation-split oos items. The CLINC test split is used only for the out-of-scope test items. No item appears in two groups (checked by assertion).
- **S2 validation in-scope items:** 500 Banking77 train examples outside that seed's 2,000-example subset, drawn with Random(555 + seed).
- **S2 confidence score:** probability of the greedy answer = product of its token probabilities up to and including the end-of-turn token. Threshold rule: answer `none_of_these` when confidence < threshold; threshold chosen to maximise overall accuracy on the validation set, candidates 0, every validation confidence value and just above 1; ties go to the lowest threshold. Chosen once per seed, saved to `s2_thresholds.json`, never re-chosen.
- **Extended prompt (C1, S1, S3):** `system_prompt(labels + ["none_of_these"])` (so `none_of_these` is one extra line at the end of the label list) followed by a blank line and "If a message does not fit any label, answer none_of_these." Claude gets the same text plus the unchanged batch JSON paragraph.
- **Test A row order:** stored in the T1 Claude batch order (Random(456)), so Claude's typo batches hold the same messages as its clean T1 batches.
- **Test B re-pairing:** equal-label pairs are broken up and re-paired greedily in shuffled order with the first remaining item of a different label; unpairable items are dropped and counted.
- **Partial Claude batches:** if a set's size is not a multiple of 25, the last batch's JSON instruction says that batch's size instead of 25 (only the number changes).
- **Claude gate:** the gate requires exit code 0, `num_turns == 1`, a JSON array of the right length, model `claude-opus-5-5` and at least n−2 allowed labels (23 of 25). Transient errors (timeouts, non-zero exit without a usage message, unparseable CLI output) first get the 30 s / 2 min / 10 min retries; any other gate failure gets one retry after 60 s.
- **Clean reference numbers** for drops are the T1 results on the same 500 messages (`results/preds_Qwen3-4B-Instruct-2507_n2000_s*.jsonl` and `results/preds_claude_code_sample500.jsonl`), read only.
- **Environment of the Claude calls (difference from T1):** the T1 Claude run was started from inside a Claude Code IDE session, so its CLI calls inherited about 17 `CLAUDE_*` session variables (for example `CLAUDECODE=1`, `CLAUDE_CODE_CHILD_SESSION=1`, a messaging socket and token). The stress pipeline clears every `CLAUDE*`/`AI_AGENT` variable except `CLAUDE_BIN`, and the tmux panes start from a minimal environment, so it does not depend on the IDE. The model, flags, prompt format and isolation are otherwise the same. It is not known whether those variables changed the CLI's behaviour in T1; the clean-vs-stressed Claude drops carry this small extra difference.
- **CLI binary:** no `claude` on PATH; the binary bundled with the Cursor extension is resolved at the start of every Claude stage.
- **Dry-run Claude call kept:** the dry run's one Claude call (Test A batch 0, made from a clean-environment tmux pane, gate passed 25/25) was made on a `typo500.jsonl` that is byte-identical to the frozen real file, with the same prompt, so by the runbook rule its predictions and raw output were carried into `results/stress/` as the real batch 0. It counts as call 1 of 90; the real pipeline resumed claude_A at batch 1.
- **Dry-run findings fixed before launch:** the report now computes the small model's clean accuracy on exactly the messages it has stressed predictions for (paired drops). No other changes were needed.

## Standing caveats about the Claude baseline

- Claude saw 25 messages per call; the small model saw one at a time.
- The Claude Code CLI adds some prompt text of its own and makes a side call to a small model.
- Claude's temperature cannot be set; the small model used greedy decoding.
- One Claude run per set; no run-to-run variation is captured.
- This is one Claude model through one CLI on a Pro subscription. It is not an API baseline and says nothing about other frontier models.
